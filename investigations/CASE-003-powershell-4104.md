## Detection objective

Verify that a meaningful Windows PowerShell Script Block Logging event (`4104`) is collected and produces an alert in Wazuh.

## Test activity

A test value was written under a user-owned, non-sensitive lab path:

```powershell
New-ItemProperty -Path 'HKCU:\Software\SOC-Lab' `
  -Name 'Case003Fresh' -Value 'Detection-Test' -PropertyType String -Force
```

This modifies **only a test value**. It is not a persistence mechanism or proof of compromise.

## Troubleshooting

Earlier searches failed to locate the expected original command, although 4104 events existed. Some matches were generated by the investigation's **own search commands**, not by the original Registry change.

A **new PowerShell session** was opened, the controlled activity was repeated with a new marker, and the original script block became visible in the Operational log. This supports the session-timing hypothesis in this lab; it does not prove that all earlier missing events had that cause.

The local screenshot included above demonstrates a separate telemetry pitfall (self-generated search logs); it **does not independently verify record 878**.

## Analyst decision

- **Fact:** The logged script attempted a Registry property change and was detected.
- **Context:** It was generated intentionally in the lab under a test path.
- **Conclusion:** **Benign authorized test**, not a malicious incident.
- **Limitation:** Event 4104 confirms logged script text; it is not a general guarantee that every PowerShell execution is visible or that every script succeeded.
