[English README](README.md) · **[خطة التطوير — In Progress](ROADMAP.md)** · [معرض الأدلة والصور](evidence/GALLERY.md) · [دليل تشغيل المختبر](operations/LAB-RUNBOOK.md)

## فكرة المشروع

أنشأت مختبرًا افتراضيًا يجمع **Windows 10** مع **Wazuh SIEM 4.14.8** لأتدرب على استلام التنبيهات الأمنية وتحليل سجلات Windows، ومقارنة الأدلة، والتحقق من صحة قواعد الكشف.

المختبر بيئة تعليمية شخصية، وليس نظام حماية لشركة حقيقية أو ادعاء خبرة وظيفية سابقة.

## النتيجة النهائية — لوحة المراقبة

## مكونات المختبر

| المكوّن | الاستخدام |
| --- | --- |
| Oracle VirtualBox | تشغيل الأجهزة الافتراضية |
| Wazuh Manager / Indexer / Dashboard | جمع التنبيهات وتحليلها وعرضها |
| Windows 10 + Wazuh Agent | مصدر الأحداث الأمنية |
| PowerShell Operational Logs | تتبع أحداث 4104 |
| Windows Security Logs | تحليل أحداث تسجيل الدخول 4625 |
| Wazuh FIM | اكتشاف تغييرات الملفات |
| Custom Rule 100100 | كشف تعديل ملف تجريبي محدد |

[مخطط بنية المختبر](architecture/README.md)

## أبرز المهارات التي يثبتها المشروع

- **تحليل سجلات Windows:** التحقق من Event ID 4625 و4104 والسياق المرافق.
- **الربط بين الأدلة:** مطابقة EventRecordID ومحتوى Script Block بين Windows وWazuh.
- **مراقبة سلامة الملفات:** مقارنة بصمات SHA-256 وتحليل Rule 550.
- **هندسة الكشف:** إنشاء Rule 100100 والتحقق منه باختبار إيجابي وسلبي.
- **تشخيص المشكلات:** تشغيل خدمات Wazuh وفحص الاتصال والسجلات.

## التحقيقات العملية

1. **[Case 001 — إعداد PowerShell Transcription](investigations/CASE-001-powershell-transcription.md):** مراجعة فشل فحص SCA وتصحيح الإعداد ثم التحقق من تحوله إلى Passed.
2. **[Case 002 — Failed Logon 4625](investigations/CASE-002-failed-logon.md):** قراءة نوع الدخول والحالة وعنوان المصدر، والتمييز بين فشل دخول محلي ومحاولة هجوم.
3. **[Case 003 — PowerShell Event 4104](investigations/CASE-003-powershell-4104.md):** إنشاء نشاط اختباري وربط Windows EventRecordID 878 بتنبيه Wazuh رقم 91843.
4. **[Case 004 — File Integrity Monitoring](investigations/CASE-004-fim.md):** تعديل ملف تجريبي ومقارنة بصمات SHA-256 والتحقق من تنبيه Wazuh رقم 550.

## قاعدة الكشف المخصصة

أنشأت قاعدة اختبارية تحمل الرقم **100100** ومستوى **9** لمطابقة تغييرات الملف:

`C:\SOC-Lab-FIM\important.txt`

اختُبرت في حالتين:
- **اختبار إيجابي:** تغيير الملف المستهدف وظهور التنبيه المخصص.
- **اختبار سلبي:** تغيير ملف آخر بالمجلد نفسه وظهور تنبيه FIM العام، من دون تنبيه جديد من القاعدة المخصصة خلال فترة الاختبار.

[ملف القاعدة وشرح اختبارها](detection-rules/README.md)

## كيف أتعامل مع التنبيهات؟

أعتمد تسلسلًا تحليليًا:

**التنبيه ← تأكيد الحدث ← جمع السياق ← تقييم الأثر ← اتخاذ القرار ← توثيق الأدلة**

اختلاف البصمة مثلًا يثبت تغيّر محتوى الملف، **لكنه لا يثبت أن مهاجمًا غيّره**. وارتفاع مستوى التنبيه لا يعني تلقائيًا أن الحادثة أخطر من كل حدث آخر.

## خطة تطوير المشروع — In Progress

اكتملت المرحلة الأساسية، لكن المشروع مستمر. وثّقت خمسة أهداف جديدة: تحليل شجرة العمليات باستخدام Sysmon، كشف نمط محاولات الدخول الفاشلة، تحليل نشاط DNS، تطوير قواعد كشف قابلة للاختبار، ثم إنشاء مساعد AI تجريبي لتحليل التنبيهات دون اتخاذ قرارات أمنية تلقائيًا.

**هذه أهداف مخطط لها وليست ميزات مكتملة.** وعند إنجاز أي هدف سنرفق الدليل والتقرير ونحدّث حالته.

**[اطّلع على خطة التطوير والأهداف الخمسة](ROADMAP.md)**

## دوري واستخدام الذكاء الاصطناعي

قمت بتجهيز المختبر وتنفيذ الاختبارات ومراجعة مخرجات Windows وWazuh والتحقق من النتائج عمليًا. استفدت من الذكاء الاصطناعي في الشرح والأمثلة التقنية واستكشاف المشكلات وصياغة أجزاء من التوثيق، **مع الاعتماد على الأدلة الفعلية من المختبر للحكم على نجاح أي خطوة**.
